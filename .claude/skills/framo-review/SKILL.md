# 검수: 기능은 기계로, 감성은 사람의 눈으로

검수는 두 가지이고 서로 대신하지 못한다.

| | 무엇을 보나 | 누가, 어떻게 |
|---|---|---|
| **① 기능 검수** | 동작하나: 잘리나, 겹치나, 넘치나, 저장되나, 오류가 나나 | 기계. 테스트와 갤러리 검사(`/framo-verify`) |
| **② 감성 검수** | 사람이 보고 무엇을 느끼나: 첫눈에 무엇이 읽히나, 휑한가 답답한가, 고급스러운가 싸 보이나, 흔한 PPT나 AI 템플릿 같은가, 쉬워 보이나 겁나나 | AI가 사람의 눈으로. 실제 화면(그림, 필름 띠)을 보고, 정해 둔 사람들의 자리에서 판단한다 |

①이 깨끗해도 ②에서 걸리면 끝난 것이 아니다. 실제로 checkCombos와 checkAssembly가 깨끗한데도 쓰는 사람이 "오른쪽이 휑하다", "위가 비어 떠 있다", "표가 빽빽하다", "AI가 만든 서식 같다"고 짚은 장이 여럿 있었다. 사람이 짚기 전에 ②가 먼저 찾아야 한다.

## ② 감성 검수: 어떻게 하나

1. **실제 화면을 찍는다.** 장은 1920×1080, 앱 화면은 1280×600(`--scrollbars`), 1366×650, 1536×730, 1920×1080. 모션은 필름 띠: 처음 1.8초를 0.15초 간격으로(첫 초점과 박자), 끝까지를 0.4초 간격으로(끝맺음과 되풀이), 차분하게와 생동감, 흰 테마와 검은 테마.
   ```bash
   npm run look -- shot "<주소>" --size 1280x600 --scrollbars --out a.png
   npm run look -- film "<갤러리 주소>" --slide N --level calm --every 150 --count 12 --out film-a.png
   npm run look -- film "<갤러리 주소>" --slide N --level lively --every 400 --count 12 --out film-b.png
   ```
   바꾼 것이 실제로 쓰이는 자리(편집기, 발표 화면, 내보낸 HTML)에서 찍는다. 부품은 혼자일 때와 다른 부품 옆일 때 모두, 조합은 seed 1~4의 모든 장을, 두 테마(white, navy), 명조(serif), 큰 글자, 강조색 두셋으로 찍는다. 대표 장만 보고 합쳤다가 신뢰를 잃은 적이 있다.
2. **만든 사람이 아닌 눈에 맡긴다.** 만든 쪽은 제 결론을 확인하는 쪽으로 본다. 그래서 감성 검수는 **`framo-reviewer` 에이전트**에게 맡긴다(`.claude/agents/framo-reviewer.md`).
   - 넘기는 것: 그림 경로, 이 장이나 화면이 무엇을 하는 곳인지(누가, 어떤 자리에서 보는지), 고치기 전의 그림(있으면).
   - 넘기지 않는 것: "이렇게 고쳐서 좋아졌다" 같은 만든 쪽의 결론.
   - 작은 확인은 직접 해도 된다. 그때도 그림을 반드시 열어 보고(Read), 아래 사람들의 자리에서 질문에 하나씩 답한다. 찍기만 하고 보지 않은 채 "통과"라고 하지 않는다.
3. **받은 판단을 고치고, 다시 찍어 다시 맡긴다.** 판단이 갈리는 디자인 결정은 혼자 고르지 않는다. 다른 방향의 시안 둘을 실제 화면으로 보여 주고 쓰는 사람이 고르게 한다.

## 누구의 눈으로 보나 (셋 다)

| 사람 | 상황 | 느끼는지 볼 것 |
|---|---|---|
| **처음 쓰는 사람** | 비개발자 직장인. 윈도우 노트북. 바쁘고, 설명서를 읽지 않는다 | 첫 화면에서 무엇을 할지 바로 보이나, 겁나거나 복잡해 보이나? 낯선 말이 있나? 막히는 순간이 있나? 잘못 눌러도 괜찮다는 안심이 드나? 저장됐다는 믿음이 가나? |
| **발표하는 사람** | 앞에 서서 말하며 넘긴다. 긴장해 있다 | 다음이 예측되나? 모션이 말의 리듬을 돕나, 끊거나 기다리게 하나? 자랑스럽게 보여 줄 만한가? |
| **듣는 분** | 3~5m 떨어진 화면. 한 장에 몇 초. 팀장, 본부장일 수도 동료일 수도 | **5초 안에** 이 장의 한 메시지가 읽히나? 눈이 처음 가는 곳이 답인가? 큰 회사가 공들인 발표처럼 느껴지나, 흔한 PPT나 AI 템플릿처럼 느껴지나? 다음 장이 기대되나? |

## 장과 컴포넌트에서 사람이 싫다고 한 것

하나라도 느껴지면 실패다.

- **비율과 여백**(가장 자주 짚힘): 한쪽(특히 오른쪽)이 휑함, 제목 아래가 비고 내용이 가운데 떠 있음, 높은 칸 가운데에 작은 것이 혼자 뜸, 양 끝으로 찢어짐, 두 덩어리가 붙어 보임.
- **빽빽함**: 표, 개요, 예상 질문처럼 줄이 많은 것이 숨 쉴 틈 없이 붙음.
- **글**: 끝 줄에 낱말 하나, 한 장에 글이 많아 한 메시지가 아님, 제목과 다투는 부품 글.
- **꾸밈 표시**: 항목 앞 강조색 막대, 축과 눈금, 자 모양 눈금, 선 끝의 큰 원이나 세로 눈금, 화살촉, 글이 든 테두리 상자나 칠한 상자, 알약 꼬리표. 정리는 글자 위계, 여백, 데이터의 옅은 줄 선으로만 한다.
- **선과 색**: 40px 안의 두 겹 선, 검정이나 굵은 장식 선, 답이 아닌 곳의 강조색, 쨍한 넓은 면.
- **전체 인상**: 예전 보고서 모양(제목 아래 점 목록, 글로 채운 두 단, 상자와 화살표, 선 그은 표), AI가 만든 서식 같은 느낌, 우리만의 결(지면의 말투, 먹과 여백)이 없음.

## 모션에서 사람이 싫다고 한 것 (필름 띠로)

- 글(제목, 본문)이 날아오거나 밀려 올라옴. 글은 제자리에서 나타나고, 움직임은 그림이 맡는다.
- 튕기거나 도는 템플릿 효과(의도한 `snap` 한 군데 말고), 빈 틀이 내용보다 먼저 보임, 듣는 사람을 기다리게 함, 끝나는 순간 자리가 튐.
- 움직임이 내용을 말하지 않고 그냥 나타나기만 함. 같은 연출이 여러 장에 되풀이됨.

## 모션 비평: 필름 띠를 보는 여덟 가지

모션은 정지 화면과 따로 본다. 기준은 `docs/MOTION.md` 맨 앞의 ‘기준’이고, 아래는 그 기준을 필름 띠에서 읽는 법이다. 기능 검사(잘림, 겹침)는 이것을 잡지 못한다.

**먼저 눈의 길을 적는다.** 칸마다(시각마다) 듣는 분의 눈이 가는 곳을 한 낱말로 적는다. 예: `0.15 제목 · 0.3 빈 축 · 0.45 큰 숫자 · 0.6 큰 숫자 · 0.9 막대 · 1.2 막대 · 1.5 (멈춤)`. 한 칸에 둘이면 초점이 갈린 것이고, 몇 칸째 같은 곳에 빈 것이 서 있으면 기다리게 하는 것이다. 그다음 여덟 가지에 좋음·보통·나쁨을 매긴다.

| 기준 | 묻는 것 | 필름 띠에서 보는 법 | 나쁨의 표시 |
|---|---|---|---|
| **초점** | 한 박자에 눈이 갈 곳이 하나인가, 첫 초점이 이 장의 답인가 | 칸마다 가장 크게 바뀐 곳을 짚는다. 눈의 길에서 답이 몇 번째에 오나 | 같은 칸에서 둘 이상이 크게 움직임, 제목이나 꾸밈이 답보다 먼저 눈을 가져감, 숫자 여럿이 같은 무게로 함께 굴러감 |
| **뜻** | 움직임이 내용을 말하나 | 움직임을 한 문장으로 말해 본다(“매출이 자라 목표에 닿는다”). 말이 안 되면 뜻이 없다 | 그냥 나타나기만 함, 데이터와 어긋난 방향(막대가 위에서 떨어짐, 시간이 거꾸로), 내용과 반대인 바탕 |
| **박자** | 이끄는 것 → 받치는 것 → 덧붙임의 차례가 있고, 기다리게 하지 않나 | 칸 아래 시각으로 잰다. 처음 0.5초 안에 읽을 것, 답은 차분하게 1.2초(생동감 1.6초) 안, 다 멈춤 3초 안 | 빈 칸, 빈 틀, 0인 숫자가 몇 칸째 서 있음, 모두 같이 시작해 같이 끝남(박자 없음), 하나 끝나야 다음이 떠남(줄 서기) |
| **이어짐** | 앞 움직임이 끝나는 자리에서 다음이 시작하나, 같은 것은 옮겨 가나 | 선 끝이 닿는 칸에 다음 것이 맺히나, 조각이 닿을 때 받는 것이 반응하나. 두 장 사이가 담겼으면 두 장의 글이 겹치는 칸이 있나 | 다음 것이 엉뚱한 곳에서 떠남, 같은 것이 사라졌다 다시 나타남, 두 장의 글이 겹쳐 보임 |
| **절제** | 크게 움직이는 곳이 한두 곳뿐인가, 꾸밈이 없나 | 다 멈춘 뒤에도 움직이는 것이 있으면 무엇이 왜인지 본다 | 모든 칸이 같은 무게로 움직임, 꾸밈 되풀이(숨 쉬는 원, 도는 고리, 반짝이, 빛), 큰 흐림, 크게 커지거나 줄어듦, 튕김 |
| **마감** | 손으로 다듬은 끝이 보이나 | 마지막 두 칸을 견준다(움직임이 끝나는 순간 자리가 바뀌나). 선 끝과 조각이 붙어 다니나, 가림막에 숫자와 글이 반쯤 잘린 칸이 있나 | 끝에서 튐, 선 끝과 조각이 어긋남, 반쯤 잘린 글자, 테마(흰·검은)에 따라 깨지는 색 |
| **움직이는 동안 읽힘** | 움직이는 중에도 글이 읽히나 | 중간 칸들에서 글이 겹치거나 뭉개지거나 흐린 덩어리로 오래 떠 있나 | 흐린 글이 몇 칸째, 움직이는 것이 글 위를 지나감, 글끼리 겹침 |
| **자리 잡기** | 길게 늦춰지며 내려앉나, 다 멈춘 뒤 머무나 | 다 멈추기 직전 칸들의 바뀜이 작아지나, 마지막 칸이 정지 화면(편집 화면)과 같나 | 넘쳤다 돌아옴, 뚝 멈춤, 멈춘 뒤에도 꼼지락거림 |

- **초점, 뜻, 절제** 가운데 하나라도 나쁨이면 그 움직임은 실패다. 나머지는 고칠 것으로 적는다.
- 차분하게와 생동감은 같은 안무의 크기 차이여야 한다. 둘의 필름을 나란히 보고, 생동감에만 다른 효과가 있으면 짚는다.
- 아는 것만 말한다. 필름 띠의 칸 사이(0.15~0.4초)에서 일어난 일은 보이지 않는다. 칸 사이에 튐이 있을 것 같으면 더 촘촘히 찍어 달라고 한다.

## 앱 화면에서 사람이 막히는 것

- 1280×600에서 잘림이나 가로 스크롤, 스크롤바가 자리를 먹음.
- 버튼 이름이 하는 일과 다름, 해요체가 아니거나 낯선 말(AGENTS.md '화면 문구'), 해결법이 없는 오류 문구, 보이지 않는 상태(저장, 연결, 진행).
- 흔한 SaaS 템플릿 모습(그러데이션, 유리, 큰 둥근 카드와 그림자, 올리면 떠오르는 카드).

## 알리는 법

사람의 말로, 누가 무엇을 느끼는지 적는다. 예: "듣는 분: 오른쪽 절반이 비어 제목보다 빈자리가 먼저 보인다(1920×1080, navy, seed 2의 14번)". 그림 경로를 붙이고, 고친 것과 남은 것을 나눈다.
