# 부탁받은 발표 자료 만들기

**부탁받은 발표 자료는 실제 업무 자료다. 저장소에 절대 넣지 않는다**(커밋, 푸시, 테스트, 예시, 스크린샷, 이슈, 커밋 메시지 모두). 훅이 `.deck`과 'Framo 발표' 경로를 막지만 거기에 기대지 않는다.

## 어디에

- `~/Documents/Framo 발표/<이름>/`에 둔다: 원고 스크립트 `make.mts`, 결과 `<이름>.deck`, 내보낸 `<제목>.html`, 고치기 전 백업 `make-before-*.mts.bak`.
- 브라우저 자동화로 열 때만 저장소의 `.playwright-mcp/`(git에서 빠짐)에 잠깐 복사하고, 끝나면 지운다.

## 만드는 법

1. **원고 스크립트**: `make.mts`가 저장소의 `src/deck/generate.ts`(`createDeck`, `makeSlide`, `emptyItem`), `src/deck/blocks.ts`(`makeBlock`, `settleDeck`), `src/deck/scenes.ts`(`withScenes`), `src/store/deckFile.ts`(`encodeDeckFile`)를 가져와 .deck을 쓴다. 실행: `cd <저장소> && npx tsx "$HOME/Documents/Framo 발표/<이름>/make.mts"`.
2. **앱에서 열기**: 홈의 '파일 열기'로 .deck을 연다 → '내보내기' → HTML → '그대로 내보내기'. 내보낸 HTML을 그 폴더에 둔다.
3. **확인**: 내보낸 HTML을 발표 모드로 열어 장마다 본다. 넘침 검사(장 상자 밖으로 나간 글)와 오류를 보고, 모션은 필름 띠로 본다. 감성은 `/framo-review`의 '듣는 분' 자리에서 본다.

## 내용 원칙

- 실제 수치가 없는 효과는 쓰지 않는다. 출처가 확인된 사례만 쓰고, 원문 링크와 날짜를 적는다.
- 한 장에 한 메시지, 글보다 그림과 숫자. 같은 그림을 돌려쓰지 않는다.
- 발표자 노트는 그대로 읽어도 되는 대본으로 쓴다.
- 쓰는 사람이 정할 것(자리표시: 이름, 숫자)은 끝에 따로 모아 묻는다.

## Framo 자체를 고칠 때

발표를 만들다 디자인이나 모션의 문제를 찾으면 원고로 피하지 말고 **Framo의 컴포넌트, CSS, 엔진을 고친다.** 그래야 앞으로 만드는 발표가 모두 나아진다. 그 고침은 저장소에 커밋하되, 발표 내용은 커밋 메시지에도 넣지 않는다.
